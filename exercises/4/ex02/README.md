# Упражнение 2: Опашкова рекурсия. Модел на средите. Вложени дефиниции. let, let\*

## 1. Видове рекурсивни процеси

Вече знаем какво е рекурсия и как тя може да се използва в Scheme. Това, което не знаем, е че имаме два основни типа рекурсивни процеси:

### 1.1 Обикновена рекурсия

При обикновената рекурсия рекурсивното извикване **НЕ Е** последната операция във функцията. Това означава, че трябва да изчакваме резултата от рекурсивното извикване, за да извършим допълнителни операции.

**Пример - факториел:**

```scheme
(define (factorial n)
  (if (= n 0)
      1
      (* n (factorial (- n 1)))))  ; Изчакваме резултата от (factorial (- n 1))
```

При `(factorial 3)` имаме следното разфъване на функцията: `(* 3 (* 2 (* 1 1)))` - натрупваме операции и заделяме памет за всяка _среда_ (за това малко по-надолу).

### 1.2 Опашкова рекурсия (Tail Recursion)

При опашковата рекурсия рекурсивното извикване **Е** последната операция в функцията. Това позволява кодът да се оптимизира и да не заделя нова памет за всяка рекурсивна стъпка.

**Пример - факториел с опашкова рекурсия:**

```scheme
(define (fact-helper n acc)
    (if (= n 0)
        acc
        (fact-helper (- n 1) (* n acc))))  ; Рекурсивното извикване е последно!

(define (factorial-tail n)
  (fact-helper n 1))
```

При `(factorial-tail 3)` имаме: `(fact-helper 3 1)` → `(fact-helper 2 3)` → `(fact-helper 1 6)` → `(fact-helper 0 6)` → `6`. Важно, е че при всяко ново извикване на `fact-helper` създаваме нова _среда_ (за това по-късно), но казано най-просто - заделяме памет за всеки от аргументите му, но в случая сме напълно "приключили" с предишното извикване и можем да изчистим старата памет. Лесно е да сравните това с предишната имплементация, при която трябва да заделяме памет за всяко ново извикване, но старите не са "приключили" и затова пазим и тяхната памет.

**Предимства на опашковата рекурсия:**

- **По-малко памет:** Не се заделя нова среда за всяко рекурсивно извикване
- **Итеративен процес:** Въпреки рекурсивния синтаксис, процесът е итеративен
- **По-бързо изпълнение:** Липса на overhead от управлението на стека на _средите_

## 2. Модел на средите (Environment Model)

Моделът на средите обяснява как Scheme управлява променливите и функциите. Всяка среда съдържа **свързвания** (bindings) между имена и стойности. Лесно е да се мисли за това като за речник от други програмни езици.

### 2.1 Глобална среда

```scheme
(define x 5)        ; Създава свързване в глобалната среда
(define (square n)  ; Създава свързване за функцията
  (* n n))
```

### 2.2 Локални среди при извикване на функции

Когато извикваме функция, се създава нова среда, която наследява от глобалната. Всъщност в тази нова среда нищо не ни пречи да влагаме дефиниции на стойности или функции.

**Нека разгледаме следният код:**

```scheme
(define x 3)

(define (get-n-plus-x n)
  (+ n x)) ; Тук използваме x от глобалната среда

(define (get-n-plus-inner-x n)
  (define x 4) ; Тук дефинираме x в локалната за функцията get-n-plus-inner-x среда
  (+ n x)) ; Тук използваме x от локалната среда.
```

И спрямо него направим следните извиквания:

- (get-n-plus-x 5) ; Връща 8, защото използва глобалният x, който е 3
- (get-n-plus-inner-x 5) ; Връща 9, защото използва локалният x, който е 4

Накратко: Когато се опитаме да достъпим стойността на даден символ се опитваме да го направим като обхождаме средите (речниците на свързвания) **отвътре - навън**. Ако не се намери такава дефиниция ще получим познатата ни грешка.


## 3. Вложени дефиниции (Nested Definitions)

Както вече видяхме, в Scheme можем да дефинираме функции и променливи **вътре** в други функции. Това създава локални среди и позволява скриване на помощни функции.

### 3.1 Синтаксис

```scheme
(define (outer-function param1 param2)
  (define (helper-function x)  ; Вложена функция
    (* x x))
  (define local-var 42)        ; Локална променлива
  (helper-function param1))    ; Използване на вложената функция
```

### 3.2 Предимства

- **Скриване на имплементацията:** Помощните функции не са видими извън основната
- **Локални среди:** Вложените функции имат достъп до параметрите на външната функция
- **По-чист код:** Групиране на свързана функционалност

**Пример - по-добре написан факториел с опашкова рекурсия:**

```scheme
(define (factorial-tail n)
  (define (fact-helper n acc) ; fact-helper наистина е helper и не е "видима" за външният свят
    (if (= n 0)
        acc
        (fact-helper (- n 1) (* n acc))))  ; Рекурсивното извикване е последно!

  (fact-helper n 1))
```

## 4. Let конструкции

`let` е специална форма, която създава локални свързвания временно. Има няколко варианта:

### 4.1 Обикновен let

```scheme
(let ((var1 value1)
      (var2 value2))
  (body))
```

**Пример:**

```scheme
(let ((x 5)
      (y 10))
  (+ x y))  ; => 15
```

### 4.2 Let\* (последователни свързвания)

```scheme
(let* ((x 5)
       (y (+ x 1)))  ; y може да използва x
  (* x y))
```
