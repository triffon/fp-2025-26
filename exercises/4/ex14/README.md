В това упражнение ще разгледаме три ключови типови класа в Haskell, които обобщават "изчисления в контекст": **Functor**, **Applicative** и **Monad**.

Миналия път работихме с **Functor** за дървета. Днес ще видим пълната картина и как тези класове ни помагат да работим елегантно с различни видове "контексти".

## 1. Какво е "контекст"?

Преди да навлезем в теорията, нека разберем какво означава "стойност в контекст":

### Maybe a - контекстът на "опционалност"

```haskell
-- Maybe Int е "число, което може да липсва"
Just 5    :: Maybe Int  -- Има стойност 5
Nothing   :: Maybe Int  -- Липсва стойност

-- Примери:
safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing      -- Деление на нула -> липсва резултат
safeDiv x y = Just (x `div` y)  -- Успех -> имаме резултат
```

**Контекстът тук е:** "Операцията може да се провали, затова резултатът може да липсва."

### [a] - контекстът на "недетерминизъм"

```haskell
-- [Int] е "множество от числа" (всички възможни стойности)
[1, 2, 3] :: [Int]  -- Три възможни стойности
[]        :: [Int]  -- Няма стойности (изчислението се е провалило)

-- Примери:
possibleMoves :: Position -> [Position]
-- Връща всички възможни ходове от дадена позиция
```

**Контекстът тук е:** "Имаме множество възможни резултати."

### IO a - контекстът на "странични ефекти"

```haskell
-- IO String е "стойност, получена чрез I/O операция"
getLine :: IO String           -- Чете от конзолата
putStrLn :: String -> IO ()    -- Пише на конзолата

-- Примери:
getName :: IO String
getName = do
    putStrLn "What is your name?"
    getLine
```

**Контекстът тук е:** "Стойността зависи от взаимодействие с външния свят."

### Either e a - контекстът на "грешки"

```haskell
-- Either String Int е "число или съобщение за грешка"
Right 42           :: Either String Int  -- Успех: 42
Left "Error!"      :: Either String Int  -- Грешка: "Error!"

-- Примери:
parseAge :: String -> Either String Int
parseAge s = case reads s of
    [(age, "")] -> if age >= 0
                   then Right age
                   else Left "Age cannot be negative"
    _           -> Left "Invalid number"
```

**Контекстът тук е:** "Операцията може да върне грешка със съобщение."

## 2. Припомняне: Functor

Класът `Functor` позволява да **трансформираме стойността вътре в контекста**, без да променяме контекста:

```haskell
class Functor f where
    fmap :: (a -> b) -> f a -> f b

-- Инфиксен оператор (същото като fmap):
(<$>) :: Functor f => (a -> b) -> f a -> f b
```

### Примери:

```haskell
-- Maybe:
fmap (*2) (Just 5)    -- => Just 10
fmap (*2) Nothing     -- => Nothing

-- Списъци:
fmap (*2) [1, 2, 3]   -- => [2, 4, 6]
fmap (*2) []          -- => []

-- IO:
greet :: IO ()
greet = do
    name <- fmap (map toUpper) getLine  -- Превръща входа в главни букви
    putStrLn ("Hello, " ++ name)
```

**Идея:** `fmap` прилага функция върху стойността в контекста, запазвайки контекста.

## 3. Applicative

Класът `Applicative` ни позволява да прилагаме **функция в контекст** към **стойност в контекст**:

```haskell
class Functor f => Applicative f where
    pure  :: a -> f a                    -- Обгръща стойност в контекст
    (<*>) :: f (a -> b) -> f a -> f b    -- Прилага функция в контекст
```

### Примери:

```haskell
-- Maybe:
pure (+10) <*> Just 5           -- => Just 15
Just (+10) <*> Just 5           -- => Just 15
Nothing <*> Just 5              -- => Nothing

-- Комбиниране на два Maybe:
(+) <$> Just 3 <*> Just 5       -- => Just 8
(+) <$> Just 3 <*> Nothing      -- => Nothing

-- Списъци (всички комбинации):
(+) <$> [1, 2] <*> [10, 20]     -- => [11, 21, 12, 22]
(,) <$> [1, 2] <*> ['a', 'b']   -- => [(1,'a'), (1,'b'), (2,'a'), (2,'b')]
```

**Идея:** `Applicative` ни позволява да комбинираме **независими** изчисления в контекст.

## 4. Монади - chain-ване на зависими изчисления

### Проблемът

И `Functor`, и `Applicative` работят добре, докато изчисленията са **независими**. Но какво, ако следващото изчисление **зависи от резултата** на предишното?

```haskell
-- Искаме да chain-нем операции:
safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing
safeDiv x y = Just (x `div` y)

-- Проблем: Как да направим 100 / 5 / 2?
-- fmap не работи, защото резултатът е Maybe (Maybe Int):
fmap (safeDiv 2) (safeDiv 5 100)  -- => Just (Maybe Int) ❌

-- Искаме просто Maybe Int!
```

### Решението: Монади

Класът `Monad` добавя оператора `>>=` (bind), който chain-ва операции:

```haskell
class Applicative m => Monad m where
    return :: a -> m a              -- Обгръща стойност (като pure)
    (>>=)  :: m a -> (a -> m b) -> m b  -- Chain-ва операции
```

### Примери с Maybe:

```haskell
instance Monad Maybe where
    return = Just

    Nothing >>= _ = Nothing
    (Just x) >>= f = f x

-- Сега можем да chain-нем:
safeDiv 5 100 >>= safeDiv 2  -- => Just 10

-- Сложен пример:
compute :: Maybe Int
compute =
  safeDiv 100 5 >>= \x ->
    -- x = 20
    safeDiv x 2 >>= \y ->
      -- y = 10
      safeDiv y 5 -- резултат = 2
-- compute => Just 2
```

## 5. Do-нотация

Haskell предлага специален синтаксис за по-четимо chain-ване:

```haskell
-- С >>= оператор (грозно):
safeDiv 100 5 >>= \x -> safeDiv x 2 >>= \y -> safeDiv y 5


-- С do-notation (четимо):
compute :: Maybe Int
compute = do
    x <- safeDiv 100 5  -- x = 20 (ако успее)
    y <- safeDiv x 2    -- y = 10 (ако успее)
    safeDiv y 5         -- резултат = 2 (ако успее)
```

Ако някоя операция върне `Nothing`, целият блок връща `Nothing`.

### Още примери:

```haskell
-- Работа със списъци от стойности:
firstNames = [(1, "Ivan"), (2, "Maria")]
lastNames  = [(1, "Ivanov"), (2, "Petrova")]

getFullName :: Int -> Maybe String
getFullName id = do
    first <- lookup id firstNames
    last  <- lookup id lastNames
    return (first ++ " " ++ last)

-- getFullName 1  => Just "Ivan Ivanov"
-- getFullName 99 => Nothing
```

## 6.1. Either монада - работа с грешки ⚠️

Either монадата е подобна на Maybe, но вместо просто `Nothing`, тя може да съхранява **съобщение за грешка**:

```haskell
instance Monad (Either e) where
    return = Right

    (Left e) >>= _ = Left e
    (Right x) >>= f = f x

-- Примери:
-- Right 5 >>= \x -> Right (x * 2)        => Right 10
-- Left "error" >>= \x -> Right (x * 2)   => Left "error"
-- Right 5 >>= \_ -> Left "failed"        => Left "failed"
```

## 7. Списъци като монада

Списъците представляват **недетерминистични изчисления** - множество възможни резултати:

```haskell
instance Monad [] where
    return x = [x]
    xs >>= f = concat (map f xs)  -- или: concatMap f xs

-- Примери:
-- [1, 2, 3] >>= \x -> [x, -x]
-- => [1, -1, 2, -2, 3, -3]

-- [1, 2] >>= \x -> [10, 20] >>= \y -> return (x + y)
-- => [11, 21, 12, 22]
```

## 8. State монада - управление на състояние

Досега видяхме монади, които се справят с липсващи стойности (`Maybe`), множество резултати (`[]`) и I/O операции (`IO`). Но какво, ако искаме да моделираме **изчисление, което променя състояние**?

### Примерът: Банкова сметка

Представете си, че пишем симулация на банкова сметка. Искаме да можем да:

- Депозираме пари (променяме баланса)
- Теглим пари (ако има достатъчно)
- Правим различни операции подред (chain-ваме трансакции)

Без монади бихме могли да вмъкваме текущия баланс през всяка функция:

```haskell
-- Без монади (грозно):
deposit :: Int -> Int -> Int
deposit amount balance = balance + amount

withdraw :: Int -> Int -> (Bool, Int)
withdraw amount balance =
    if balance >= amount
    then (True, balance - amount)
    else (False, balance)

-- Използване:
let balance0 = 0
    balance1 = deposit 100 balance0
    (ok1, balance2) = withdraw 30 balance1
    balance3 = deposit 50 balance2
    (ok2, balance4) = withdraw 150 balance3
-- Ужасно! Трябва ръчно да прокарваме balance1, balance2, balance3...
```

### State монадата

State монадата капсулира "изчисление, което чете и променя състояние":

```haskell
newtype State s a = State { runState :: s -> (a, s) }
```

**Какво означава това?**

- `State s a` е **изчисление** (ф-ция), което:
  - Има единствена стойност функцията `runState`, която:
    - Получава състояние от тип `s`
    - Връща резултат от тип `a`
    - И ново състояние от тип `s`

**Пример:** `State Int Bool` е изчисление, което:

- Работи със състояние `Int` (например баланс)
- Връща резултат `Bool` (например дали операцията е успешна)

5. Теглим 150 (неуспех, нямаме достатъчно!) → баланс = 120
6. Депозираме 80 → баланс = 200
7. Резултатът е низ с информация за операциите и финален баланс 200

  - `deposit X` - депозира X пари

1. **Крайна наличност** по сметката след всички операции

3. **Сумарно разходите** (сбор на всички успешни тегления)

```

deposit 100
withdraw 30
deposit 50
withdraw 200
deposit 25
withdraw 40
```

```haskell
calculateFromFile :: FilePath -> IO (Int, Int, Int)

-- Изпълнение:
-- calculateFromFile "transactions.txt"
-- => (155, 175, 70)
--     ^крайна наличност
--         ^сумарно депозити (100 + 50 + 25 = 175)
--              ^сумарно тегления (30 + 40 = 70, теглене на 200 е неуспешно)
```

**Обяснение:**

1. Започваме с 50

8. Крайна наличност: **155**, Депозити: **175**, Тегления: **70**
