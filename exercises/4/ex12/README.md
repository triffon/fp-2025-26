## 1. Алгебрични типове данни (ADTs)

В Haskell можем да дефинираме собствени типове данни чрез ключовата дума `data`. Те се наричат "алгебрични", защото се изграждат чрез суми (алтернативи) и произведения (комбинации) от други типове.

### 1.1 Изброен тип (Sum Type)

Най-простият вид е еквивалентът на `enum` в други езици. Типът има няколко възможни стойности (конструктори).

```haskell
data Color = Red | Green | Blue

-- Функция, която работи с нашия тип
colorName :: Color -> String
colorName Red   = "The color of blood"
colorName Green = "The color of grass"
colorName Blue  = "The color of the sky"
```

### 1.2 Конструктори с параметри (Product Type)

Конструкторите могат да приемат аргументи. Това позволява да съхраняваме данни в нашия тип.

```haskell
-- Point приема два Double аргумента (x и y координати)
data Point = Point2D Double Double

-- Shape може да бъде Circle (с център и радиус) или Rectangle (с два срещуположни ъгъла)
data Shape = Circle Point Double       -- Център, Радиус
           | Rectangle Point Point     -- Долен ляв, Горен десен
```

### 1.3 Синтаксис със записи (Record Syntax)

За да не се налага да помним реда на полетата, можем да им дадем имена:

```haskell
data Person = Person {
    firstName :: String,
    lastName  :: String,
    age       :: Int
}

-- Това автоматично създава функции за достъп (getters):
-- firstName :: Person -> String
-- lastName :: Person -> String
-- age :: Person -> Int
```

## 2. Типови класове (Type Classes)

Както вече знаем от [упражнение 8](../ex08/) Типовите класове в Haskell са подобни на интерфейсите в Java/C#, но са по-мощни. Те дефинират поведение, което даден тип трябва да поддържа.

### 2.1 Припомняне на основни класове

- `Eq` - за сравнение за равенство (`==`, `/=`)
- `Show` - за превръщане в низ (`show`)
- `Ord` - за подредба (`<`, `>`, `<=`, `>=`)
- `Num` - за числови операции (`+`, `-`, `*`)

### 2.2 Deriving (Автоматично извеждане)

Haskell може автоматично да генерира имплементация за някои стандартни класове:

```haskell
data Animal = Cat | Dog | Mouse
    deriving (Show, Eq)

-- Сега можем да правим:
-- show Cat      => "Cat"
-- Cat == Dog    => False
```

### 2.3 Ръчна инстанция (Instance)

Ако искаме специфично поведение, дефинираме инстанцията ръчно:

```haskell
data TrafficLight = RedLight | YellowLight | GreenLight
  -- Искаме Eq да работи стандартно
  deriving (Eq)

-- Но искаме Show да извежда нещо специално на български
instance Show TrafficLight where
  show RedLight = "Stop!"
  show YellowLight = "Ready..."
  show GreenLight = "Go!"
```

## 3. Параметричен полиморфизъм

Можем да дефинираме типове, които работят с _произволен_ друг тип. Това се нарича параметричен полиморфизъм (подобно на Generics/Templates).

```haskell
-- Кутия, която може да съдържа стойност от всякакъв тип 'a'
data Box a = Empty | Has a
    deriving (Show)

-- Box Int
b1 = Has 5
-- Box String
b2 = Has "Hello"
-- Box Shape
b3 = Empty
```

Едни от най-използваните полиморфни типове са `Maybe` (за опционални стойности) и `Either` (за резултат или грешка).

```haskell
data Maybe a = Nothing | Just a
data Either a b = Left a | Right b
```
